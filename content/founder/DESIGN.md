## 2. タイトル運用ルール

- 各シリーズのタイトルは**すべて仮タイトル**として管理する。確定させない。
- 順序は必ず **STORY → TITLE**。本文を完成させた後に、
  - 内容を一番正確に表しているか
  - 本人の言葉として違和感がないか
  - 続きを読みたくなるか
  を基準に本人が最終決定する。
- タイトルに合わせて事実やエピソードを加工することは禁止。

## 4. 投稿規模の扱い方

約75投稿は「制作ノルマ」ではなく、現時点で原典から抽出可能な**コンテンツ資産数の見積り**として管理する。

- 一気に75投稿を作らない。
- 同じ話を言い換えるだけの水増しをしない。
- まず**第1制作バッチ（10〜15本程度）**を作り、以下を確認してから残りの制作方針を決める。
  - 本人らしさ
  - 読みやすさ
  - 投稿の長さ
  - 反応
  - OUKAとの接続の強さ

## 6. MASTER STORYの成長運用（継続入力の処理パイプライン）

MASTER STORYは完成済み固定文章ではなく、継続的に成長する原典として扱う。本人から新しい人生経験・記憶・人物・考え方・事業思想が入力されるたびに、以下の順で処理する（詳細は `interview/00_system.md`）。

```
RAW VOICE（本人の生の発言）
  → FACT / MEMORY / PERSON / FEELING に分解
    → MASTER STORYへの追加・修正候補
      → 所属SERIES（親子構造含む）の判定
        → CONTENT ANGLE（何の切り口で使えるか）
          → 媒体適性（Website / Threads / OUKA FB・IG / 個人FB）
            → 公開可否
              → SNS候補
```

- 新しい話が入るたびにMASTER STORY全文を書き直す必要はない。**差分管理**（該当セクションへの追記、変更履歴ログへの記録）を基本とする。
- 矛盾・不明点が見つかった場合は勝手に直さず `[要確認]` を付ける。
- 事実として確定していないものをタイトルやセクション構成に先回りして書き込まない（例：「大学」セクションは現時点でMASTER STORYに事実記載がないため `founder_story_page/page_structure.md` 内で保留扱いとしている）。

## 7. Founder Interview機能（概要）

目的は「文章を作ること」だけでなく、本人の判断基準・価値観・思考モデルを長期的に蓄積すること。詳細仕様・質問バンク・判断基準台帳・思考の変化ログは `interview/` 配下で管理する。今回のスコープでは、自動投稿・外部SNS API連携・複雑なAIエージェント化は行わない。「本人を正確に記録する仕組み」の完成を優先する。

**媒体の役割（重要ルール）**
- Website：最も詳しい原典。Founder Story専用ページの各セクションになる。
- Threads：1投稿1テーマ。実体験の一文から入る。名言の量産はしない。
- OUKA公式FB/Instagram：学校公式。「代表の経験 → そこから得た考え → OUKAの教育」の構造。Instagramは9枚カルーセル（①HOOK ②〜⑥STORY ⑦LESSON ⑧OUKAとの関係 ⑨CTA）。**毎投稿OUKAへ誘導する必要はない。**
- 個人Facebook：OUKA公式と完全分離。学校の宣伝色を弱くする。「こういう人間がいる／こういう経験をした／だからこう考えるようになった」を先に置き、OUKAへの接続は必須にしない。

**最重要ルール**：本人の人生をOUKAの広告にしない。事実→経験→考え方の順で構成し、結果としてOUKAの教育につながる場合のみ言及する。
