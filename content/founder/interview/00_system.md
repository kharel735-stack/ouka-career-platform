# Founder Interview System｜運用仕様

## 目的

これは単に「カレル・アニスについての文章を作る」ための仕組みではない。長期的な目的は、本人の

- 人生経験・記憶・人間関係
- 失敗・成功
- 判断基準
- 仕事観・日本観・ネパール観・教育観・人材観・経営観
- お金に対する考え方
- 採用基準・人を見る基準
- 怒るポイント／許せること・許せないこと
- 日本社会から学んだこと
- 将来やりたいこと
- 過去の意思決定とその理由

を少しずつ蓄積し、「AIの中にカレル・アニス本人の思考モデルを作っていく」ことである。

**重要な制約**：これは本人の代わりに勝手に意思決定するAIを作るものではない。最終判断は必ず本人が行う。AI側が目指すのは「過去のあなたの経験・発言・判断基準から考えると、あなたならAを選ぶ可能性が高い。理由は○○」まで説明できる状態であり、それ以上ではない。

**今回のスコープ**：Founder Story OS／MASTER STORY／Founder Interview機能／SERIES管理／SNS展開設計、ここまで。自動投稿・外部SNS API連携・複雑なAIエージェント化は行わない。

---

## 入力処理パイプライン（RAW VOICEの処理）

本人から新しい話（RAW VOICE）が入るたびに、以下の順で処理する。

```
1. RAW VOICE            本人の生の発言・記憶
2. FACT / MEMORY / PERSON / FEELING に分解
3. MASTER STORYへの追加・修正候補
4. 所属SERIES（親子構造含む）の判定
5. CONTENT ANGLE        どの切り口で使えるか
6. 媒体適性             Website / Threads / OUKA FB・IG / 個人FB
7. 公開可否
8. SNS候補
```

- MASTER STORYは毎回全文を書き直さない。**差分管理**（該当セクションへの追記、または `master_story.md` 末尾の変更履歴ログへの記録）を基本とする。
- 矛盾・不明点は勝手に直さず `[要確認]` を付ける。

## 掘り下げの処理（FACTだけで終わらせない）

事実だけを集めて終わらせず、可能な範囲で以下まで掘り下げる。

```
FACT           何が起きたか
EXPERIENCE     具体的にどう関わったか
EMOTION        その時どう感じたか
LESSON         そこから何を学んだか
VALUE          今、何を大事にしているか
DECISION RULE  それが今の判断にどうつながっているか
```

例えば本人が価値観（例：「時間を守らない人が嫌い」）を口にした場合、それだけを記録して終わらない。「そう思うようになった具体的な出来事はありますか？」と聞き、FACT→EXPERIENCE→EMOTION→LESSON→VALUE→DECISION RULEまで辿る。

確認できたVALUE／DECISION RULEは、なぜそう考えるに至ったか（ORIGIN）とセットで `decision_rules.md` に保存する。

## 矛盾・変化の扱い（THOUGHT EVOLUTION）

本人の考え方は時間とともに変わり得る。「昔はこう考えていた」「今はこう考えている」という変化も重要なデータである。矛盾しているからといって古い考えを削除しない。`thought_evolution.md` に「THOUGHT EVOLUTION」として両方残す。

## 質問の作り方

- 「あなたの人生観は何ですか？」のような抽象的すぎる質問を連発しない。
- 具体的な記憶を引き出す質問にする（例：「日本に来て最初に仲良くなった友達はどんな人でしたか？」）。
- 音声入力で答えやすい、具体的な問いにする。
- **1回につき1〜3問まで**。大量の質問を一度に出さない。
- **記憶を連鎖させる**。直前の話題と関連性の高い質問を優先する（例：話が「辻先生」なら、次も中学・食事・友人関係など近い記憶から聞く。突然「会社経営のKPI」のような無関係な質問はしない）。
- 同じ質問を繰り返さない（`question_bank.md` のステータス管理で防ぐ）。

## 出力先（将来的な利用範囲）

質問で得られた情報は、将来的に以下へ利用できるよう構造化して保存する：MASTER STORY／Founder Profile／Founder Philosophy／Founder Decision Rules／SNS／Website／講演／会社紹介／採用／教育方針／経営判断。

## 記憶に基づくエピソードの扱い（重要な注意）

本人の記憶に基づく再構成（特に第三者のセリフ）は、逐語の引用ではない。コンテンツ化する際、直接話法として過度に脚色・演出しない。「〜という趣旨のことを言われた」のように、趣旨を損なわない範囲の表現を基本とする（例：辻先生のエピソード）。
